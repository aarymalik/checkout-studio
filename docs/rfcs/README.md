# RFCs

Architectural decisions that are expensive to reverse are written down before they are made.

The process — when an RFC is required, how it is reviewed, and what each status means — is defined in [contributing.md](../contributing.md).

## Writing one

```bash
cp docs/rfcs/template.md docs/rfcs/0001-short-title.md
```

Open it as a pull request against `docs/rfcs/`. Discussion happens in review.

Rejected RFCs are merged, not deleted. "Why don't we just…" is a question that gets asked repeatedly, and a rejected RFC is the cheapest possible answer.
